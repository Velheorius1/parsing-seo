# 🔴 Дубль-краулер в Docker 5 недель отменял все фиксы шума (2026-07-17)

**TL;DR:** на VPS параллельно крон-краулеру жил контейнер `tender-crawler` (образ `crawler-crawler`, собран **07.06**), который каждые 2 часа краулил ВСЕ источники и слал алерты **кодом от 7 июня** — без авто-мьюта, 3-tier роутинга, e-shop демоута и V1-verifier. Он краулил чаще, поэтому **алертил ПЕРВЫМ**, тендер попадал в БД как «не новый», и исправленный крон-краулер до него уже не доходил. Итог: большинство алертов Данияра шло мимо всех фиксов. **Контейнер остановлен 17.07.**

## Как обнаружено
Симптом: источники, замьюченные неделями (Мин сельхоз 25❌/0✅ с 25.06, E-Birja с 29.03), продолжали пушиться ~100% — при том что `get_active_mutes()` вручную возвращал 8, а `[Route]` в логе показывал `0 push / 3 digest (8 muted sources)` — то есть **мьют работал**.

Ложные гипотезы, опровергнутые по пути (не повторять):
1. ~~`get_active_mutes` возвращает пусто~~ → возвращает 8, даже под 20 конкурентными вызовами.
2. ~~Рассогласование `t.source` со строкой мьюта~~ → байт-в-байт совпадает (len 15==15).
3. ~~`_to_push` неверен~~ → на канонической «TG: Мин сельхоз» даёт `False` (=дайджест). Корректен.
4. ~~Тайминг (мьют пересёк порог недавно)~~ → мьют с 25.06, пушей после — 31/31.
5. ~~Молчаливый fail-open при Supabase-таймауте~~ → правдоподобно, но **не причина** (см. ниже).

**Что вскрыло:** строки появлялись в 06:04/08:03 — крона на это время нет, в `parsing-seo.log` тишина, `journalctl` не показывает запуск. `docker ps` → `tender-crawler | Up 5 weeks`. В его коде: `grep -c get_active_mutes /app/crawler/core/notifier.py` = **0**. Его лог: `[Alerts] Sent 11/11 alerts (seq #6106-#6116)` — ровно те seq, что «пушились несмотря на мьют». Ни `[Route]`, ни `[NoPush]`, ни `[Digest]` — этой логики в образе просто нет.

## Почему git-автодеплой не спасал
`*/5` cron делает `git pull` в `/opt/parsing-seo` — обновляет код для **крон-краулера**. У контейнера код **вшит в образ** (`/app/crawler/...`, mtime `Jun 7 04:58`), маунта нет → он заморожен навсегда и обновляется только пересборкой образа, чего никто не делал.

## Фикс (17.07)
1. `docker update --restart=no tender-crawler` + `docker stop tender-crawler` → `exited`, сам не встанет. **Обратимо:** `docker start tender-crawler` (но НЕ надо — см. ниже).
2. Частота крона поднята с 3×/сут до каждых 2ч (компенсация свежести, которую давал контейнер):
   - `0 */2 * * * run_crawl.sh --no-telegram` (API-источники)
   - `30 */2 * * * run_crawl.sh --only-telegram` (TG-каналы)
   - бэкап: `/root/crontab.bak.2026-07-17-094129`

**Не поднимать контейнер обратно.** Его архитектура (код в образе) несовместима с git-автодеплоем: он неизбежно замерзает и снова начнёт отменять фиксы. Единственный краулер = крон + `/opt/parsing-seo` + автодеплой.

## Правило (в error-log)
**Дубль-сервис со вшитым кодом молча отменяет весь прогресс и невидим в логах основного пути.** Симптом-маркер: поведение прода не соответствует коду прода, а логи основного пути «чистые». Диагностика: `docker ps` + сверить mtime кода сервиса с `git log` прода + сверить `alert_seq`/msgid из БД с логами КАЖДОГО процесса, а не только ожидаемого. Родственный инцидент: feedback_bot крутил Apr-19 код (stale-process guard в healthcheck ловит systemd, но **не ловил docker**).

## Хвост №3 (вскрылся 18.07): контейнер сломал Telegram-сессию хоста
Контейнер монтировал `/opt/parsing-seo/crawler/sessions` (общий session-файл) и нёс **Telethon 1.43.2**, хост — 1.42.0. Незадолго до остановки (первые ошибки ≤15.07 18:30) 1.43 мигрировал sqlite-схему сессии на **v8** (6 колонок, `tmp_auth_key`) → хостовый 1.42 (v7, 5 колонок) падал на КАЖДОМ TG-канале: `too many values to unpack (expected 5)` (19 ошибок/прогон, WARNING per-source — крол «зелёный», exit=0). Пока контейнер жил, TG-алерты делал он — поломка крон-пути была замаскирована; после стопа TG-покрытие тихо стало нулевым. **Фикс 18.07:** бэкап сессии + `pip install telethon==1.43.2` в хостовый venv (пин `>=1.34,<2.0` позволяет) → 0 unpack-ошибок, бэклог 2.5 суток докролен за 69 мин. **Урок:** у дубль-сервиса проверять не только код, но и **общие изменяемые файлы состояния** (sessions, кэши, sqlite) — version-skew библиотек через shared state ломает основной путь даже после остановки дубля.
