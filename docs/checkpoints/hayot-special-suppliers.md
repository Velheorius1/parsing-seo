# Hayotbirja — спец/зелёные/чёрные поставщики (реверс-аудит)
Дата: 2026-06-11. Только чтение, анонимные curl. Host: api.hayotbirja.uz

## ref_special_suppliers — структура (read limit=2)
curl -s -X POST https://api.hayotbirja.uz/rpc -H 'Content-Type: application/json' \
  -d '{"id":1,"jsonrpc":"2.0","method":"ref","params":{"ref":"ref_special_suppliers","op":"read","limit":2,"offset":0}}'

Поля записи:
  id, inn, name, contacts, reason, description
  meta: { registered(bool), bank_accounts[], products[] }
  products[]: { product_name, product_code(ЕНКТ), partners[], description(правовое основание: ПП/ПКМ/УП-номер) }

Пример: id=3558 "O`zGEORANGMETLITI МЧЖ" inn=207080398, продукт 71.12.17.000-00001 (инж.проектирование), основание ПП-3145 от 24.07.2017
Пример: id=3559 "Gazli Gas Storage МЧЖ КК" inn=305810222, продукты 52.10.12.120 (хранение газа), основание ПКМ-131

ВЫВОД: подтверждено — это реестр единственных/спец-поставщиков, каждый закреплён правительственным актом (ПП/ПКМ) под конкретный product_code ЕНКТ.

## Объёмы каналов (op:count)
curl ... '{"method":"ref","params":{"ref":"ref_special_suppliers","op":"count"}}' -> count=1608
offset=3000 -> [] (всего 1608 записей, offset cap не достигается)

## ref_green_suppliers — структура (read limit=2)
op:count -> ОШИБКА "Действие запрещено ... операция count ... отсутствует в whitelist" (count не разрешён для этого ref).
read работает. Поля: respublica, name, inn, district.
Это реестр "Ягона буюртмачи" (единый заказчик) — инжиниринг-компании хокимиятов по капстроительству. НЕ поставщики печати.
Пример: "Андижон вилояти хокимлиги Ягона буюртмачи..." inn=200238014

## ref_bad_suppliers — ЧЁРНЫЙ СПИСОК (count=14)
Поля: id(=ИНН), code(=ИНН), name, note(правовое основание ORQ-684 ст.48), date_begin, date_end
Пример: "Pro Max Best Shop MCHJ" inn=310569955, с 2025-09-23, основание ORQ-684-son 48-modda
ВЫВОД: компактный реестр недобросовестных (14 записей) — годен для комплаенс-проверки контрагентов по ИНН.

## ref_green_suppliers объём — оценка через offset-probe
offset 1500=есть, 2200/2700 (см вывод), 3000=пусто. Объём ~1500-2700 записей.

## Ограничения API (важно для рецепта)
- limit max = 100 (limit>100 -> error "Значение должно быть <= 100"). 1608 записей = 17 страниц по 100.
- filters ДОЛЖЕН быть ОБЪЕКТОМ (не массивом). Поддерживается ТОЛЬКО фильтр "inn" (exact).
  filters product_code -> 500 "фильтр отсутствует в списке". filters name -> то же. search param -> не поддерживается.
- op:count работает для special/bad, но ЗАПРЕЩЁН для green ("операция count отсутствует в whitelist").
- ВЫВОД: поиск печатных поставщиков = только клиентский скан всех 1608 (product_code лежит в meta.products[], серверного фильтра нет).

## РЕЦЕПТ периодического снапшота (для адаптера)
Endpoint: POST https://api.hayotbirja.uz/rpc  (Content-Type: application/json, анонимно, без UA)
Body: {"id":1,"jsonrpc":"2.0","method":"ref","params":{"ref":"<REF>","op":"read","limit":100,"offset":<M>}}
Пагинация: limit MAX=100; offset шаг 100 до пустого result. filters={"inn":"..."} единственный рабочий (нельзя по product_code/name).
  - ref_special_suppliers: 1608 записей = 17 страниц (offset 0..1600). op:count работает (быстрая проверка дельты).
  - ref_green_suppliers: ~2700-3000 = 28-30 страниц; op:count ЗАПРЕЩЁН (читать до пустого).
  - ref_bad_suppliers: 14 записей = 1 страница; op:count=14.
Извлечение печати: клиентский фильтр meta.products[].product_code startswith (17.12,17.21,17.22,17.23,17.29,18.1,58.1).
Частота: РАЗ В НЕДЕЛЮ достаточно (реестр меняется правит.актами ПКМ/ПП — медленно; свежий ПКМ-897 от 27.12.2024).
  Дельта-детект дёшево: special op:count + bad op:count раз в день; полный 17-стр снапшот раз в неделю.
Ключи записи (id-space): id (внутр.), inn (ИНН — стабильный join-ключ к Bitrix/контрагентам), product_code (ЕНКТ).
Deep-link карточки закупки (НЕ для ref): POST /urpc {"method":"get_proc","params":{"proc_id":X}} — отдельный id-space (proc_id), к этим ref не привязан.

## Подводные камни
- limit>100 -> bad_params "<=100". filters обязан быть ОБЪЕКТОМ (не массив), иначе "Значение должно быть обьектом".
- filters поддерживает только inn; product_code/name/search -> error (500/не поддерживается).
- op:count для green запрещён -> объём только перебором offset.
- Большие страницы (~65КБ/100зап) грузятся ~1-3с; параллельный фон-цикл в bash может зависать — фетчить последовательно с -m 25.
- offset cap 3000 заявлен платформой; для special (1608) и bad (14) не достигается; green упирается близко к cap.
- registered флаг != "активен": 60% записей registered=False (вероятно историч./филиалы), но всё равно действующие моно-основания.
