## Cooperation: целевая архитектура («полноценно пользоваться»)

**Сегодня используем 5 публичных эндпоинтов** (GetAllPlanSchedule, GetAllOffer, GetLotsInTrade, auction/public/lots, eshop/lots/active) + photo/price offer-join. **Не используем:** GetLotInfo (детали лота: позиции, требования, адрес — за E-IMZO), кабинет (ставки, наши лоты).

1. **Детали лота в алерт (лечит «сложно смотреть какие они»):** после оживления токена — GetLotInfo для каждого АЛЕРЧЕННОГО лота (только ~13/день, не для 15k) → позиции/объёмы/требования прямо в алерт + Vercel-карточку. Реализация: enrichment-шаг в fetch_cooperation по паттерну ETender P7.
2. **Авторизация — из «кривой» в устойчивую:** refresh-токен flow (уже есть в store) → полный E-IMZO только при протухшем refresh; alert при фейле; healthcheck-FAIL на мёртвый токен.
3. **⚔️ Bid-war на Cooperation:** у нас на cooperation есть свои позиции/участия → тот же watch_our_lots-паттерн: GetLotsInTrade фильтр по нашему ИНН/названию + отслеживание ставок конкурентов в лотах, где мы участвуем (требует кабинет-API — после токена; разведать эндпоинты ставок).
4. **Оферты:** прекратить складировать 21k/мес целиком; хранить только print-scope (STRONG-регекс) + топ конкурентов (competitive intel). −80% мусора в БД.
