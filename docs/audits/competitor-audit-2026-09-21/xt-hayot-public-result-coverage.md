# XT-Xarid / Hayotbirja: граница публичного аудита победителей

Единичный read-only JSON-RPC probe `ref_tender_public` от 21.09.2026 подтвердил
структуру публичной ленты. Она отдаёт предмет, заказчика (`company_name` и
`company_inn`), статус, сумму, даты и `meta.good_maps`, но не содержит ни
`winner`, ни `provider`, ни `supplier`, ни ИНН исполнителя. Это совпадает с
явной обработкой в `crawler/adapters/jsonrpc.py`: площадка даёт `status` и
`last_price`, но не победителя.

| Вопрос | Подтверждённый ответ |
| --- | --- |
| Можно ли найти победы заданных конкурентов по публичному JSON-RPC? | Нет: нет идентификатора исполнителя для exact-INN join. |
| Можно ли использовать ленту для будущих алертов? | Да: есть открытые процедуры, позиции, дедлайн и сумма. |
| Hayot и XT — два независимых архива? | Нет для тендерной SPA-витрины: Hayot является зеркалом XT, их external IDs пересекаются; данные дедуплицируются. |
| Означает отсутствие найденных побед «0 за год»? | Нет. Это `unobservable_publicly`, не ноль. |

## Следующее допустимое действие

Для аудита побед нужен один из первичных источников с раскрытым исполнителем:
публичная карточка закрытой процедуры, протокол/договор, либо авторизованный
реестр площадки. До появления такого источника XT/Hayot остаются в матрице
охвата как **открытый спрос**, но исключаются из количественной статистики
побед конкурентов. Не подменять это fuzzy-сопоставлением названий или
догадкой по заказчику.
