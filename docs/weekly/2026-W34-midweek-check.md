## Находка №1 (главная): латентный баг W34 стоял в ОДНОМ ряду от потери 500 строк

Отчёт W34 оставил тот же класс бага (`21000` → откат всего батча) в двух файлах
осознанно, по правилу «один баг за раз». Проба живого апстрима 19.08 показала,
что в одном из них он не теоретический, а заряженный.

**Замер.** `UZEX Предквалификации` отдают **1001 строку при 1000 уникальных**:
ключ `uzex-prq-98829` приходит дважды. Позиции дублей — **индексы 499 и 500**,
то есть ровно по разные стороны границы батча в 500 строк:

```
KEY uzex-prq-98829 at indices [499, 500] -> batches [0, 1]
  same batch? False
```

Сегодня это безвредно. Сдвиг апстрима на одну строку — и обе копии попадают в
один батч, Postgres отвечает `21000` и откатывает батч целиком.

**Стаб-тест ДО/ПОСЛЕ** (тот же модуль, подменён только клиент Supabase):

| Случай | ДО фикса записано | ПОСЛЕ записано |
|---|---|---|
| дубль 499/500 (как сейчас) | 1001 | 1000 |
| дубль 498/499 (внутри батча) | **501 из 1001 — минус 500** | 1000 |
| без дублей (здоровый путь) | 1001 | 1001 |

Здоровый путь не тронут — это условие того, что фикс безопасен.

**Применено** (`7481965`): дедуп по `(external_id, source)` перед батчингом —
повтор канонического паттерна `crawler/core/db.py:211`, тот же, что закрыл
Cooperation в `3a4eb7c`. **Прод-прогон через резидентный прокси 18:28:**

```
Fetched 1001 -> [Upsert] Deduplicated 1001 -> 1000 -> Upserted 1000, Errors: 0
```

**Попутно подтверждён фикс W34.** Откаты `21000` шли в
`/var/log/parsing-seo-proxy.log` ежедневно по 2–5 штук вплоть до 17.08 09:34:55,
и с этого момента **ноль за двое полных суток** (18.08, 19.08). Прошлый отчёт мог
опереться только на один прогон — теперь это подтверждено окном.

Тот же пробел остаётся в `crawler/scripts/fetch_ebirja_contracts.py:330`,
непроверенный на дубли. Не трогал — один баг за раз.

## Находка №2: мьют `Hayotbirja отбор` прячет профильный лот со score 95

Аудит 6 активных мьютов: пять чисто OFF-scope (новостные каналы, курсы валют,
провода). Шестой — нет.

`Hayotbirja отбор` заглушён по 3 ❌ при 0 ✅. Среди его свежих лотов:

> «Омонатларни кафолатлаш агентлиги учун **босма ва реклама-ахборот
> материалларини** тайёрлаш ҳамда етказиб бериш бўйича корхона танлаш»
> — `alert_seq=6349`, **`relevance_score=95`**, hayotbirja.uz/procedure/8117431/core

Изготовление печатных материалов для Агентства по гарантированию вкладов —
это ровно наш скоуп, и классификатор сам оценил лот на 95. Мьют не отменяет
ingestion, но `_route_to_push` (`notifier.py:1396`) уводит источник из push в
дайджест, то есть мгновенного алерта по лоту не было.

**Мьют снят 19.08.** Автономный прогон снова получил отказ
permission-классификатора — ПЯТЫЙ раз подряд (W30, W31, W32, W33 и сегодня),
обходить не стал; Данияр подтвердил в тот же день, и мьют снят штатным
`unmute_source`. Верификация не по выводу скрипта, а через `get_active_mutes()`:
активных мьютов 6 → 5, `Hayotbirja отбор` в множестве отсутствует, счётчик
`neg=3, pos=1` (один ✅ = постоянное вето, авто-мьют его больше не заглушит).

Системная дыра при этом не закрыта: recall-guard пятую неделю подряд неисполним
автономно и каждый раз требует ручного подтверждения. Лечится Bash-permission
правилом на `crawler.scripts.unmute_source`.

## Находка №3: FP этой недели — не «шумный источник», а одна товарная группа

Все 4 FP из выборки n=12 пришли из `UZEX Э-магазин бумага и изделия` и все —
сырьевая бумага: обёрточная ×2, самоклеящаяся ×2, у всех в поле `organization`
стоит страна (РОССИЯ, КИТАЙ, ФРАНЦИЯ, ВИРГИНСКИЕ ОСТРОВА), а не заказчик.

Но глушить источник нельзя: из 56 его алертов в последних 400 идут и профильные —
бейджи, бланки сертификатов, бланки строгого учёта, обложки для переплёта,
«Коробка из гофрированного картона», «Услуга по изготовлению коробок».

Из показанного топ-15 названий (31 из 56 строк) под дословные пункты NOT-листа
попадают **не менее 13**: обёрточная бумага 5, немелованная 2, самоклеящаяся 2,
тетради 4. Точную долю по всем 56 не считал — счётчик показал только топ-15,
поэтому «не менее», а не «23%».

Это тот же класс, что находка №3 в W34 («FP — дословные пункты NOT-листа»), но
теперь названо место: не источник целиком, а товарная группа внутри него.

## Идеи (проверяемые, НЕ применены)

1. **Дедуп в `fetch_ebirja_contracts.py:330`** — последний файл этого класса.
   Сначала проба апстрима на дубли (как сегодня для UZEX), фикс только если дубли
   есть. Проверка: стаб-тест ДО/ПОСЛЕ + прод-прогон. Эффект: закрывает последний
   канал молчаливой потери до 500 строк.
2. **Явная группа в промпте: «бумага как товар (обёрточная, немелованная,
   самоклеящаяся) — НЕ наш»**, тетради там уже есть. Риск: правка промпта влияет
   на всю классификацию. Проверка обязательна replay-ом на 56 алертах источника —
   FP должны упасть, а бейджи/бланки/гофрокоробки остаться. НЕ применять без замера.
3. **Порог авто-мьюта не смотрит на score.** `Hayotbirja отбор` заглушён тремя ❌,
   имея при этом лот на 95. Предложение: не глушить источник (или авто-снимать
   мьют), если у него за окно есть лот со score ≥ 90. Это закрывает дыру, которая
   пятую неделю подряд требует ручного вмешательства Данияра.
