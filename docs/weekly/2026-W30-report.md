## Находка №1 (главная) — обвал precision 7.8 → 1.5 = смена определения FP, НЕ регрессия качества

`crawler/scripts/weekly_metrics.py:163` считает precision как `1 − false_positives/total`. Коммит **`3e0a2cf` (2026-07-16, mid-W29)** переопределил `false_positives` в `crawler/core/feedback.py`:

```
- if r["original_label"] in ("demand","customer_request") and r["corrected_label"] == "ad"
+ if r["corrected_label"] in ("ad", "irrelevant")
```

Старое условие почти никогда не выполнялось (`original_label` хранил `message_type`, который значений `demand`/`customer_request` не давал) → FP систематически занижались. Новое ловит любую пометку `ad`/`irrelevant`.

Пересчёт по НОВОМУ определению на исторических данных — падения нет, полка держится с W26:

| Неделя | Всего | FP | FP-rate |
|---|---|---|---|
| 2026-W26 | 221 | 168 | 76% |
| 2026-W27 | 201 | 188 | 94% |
| 2026-W28 | 123 | 115 | 93% |
| 2026-W29 | 206 | 182 | 88% |
| 2026-W30 | 8 | 4 | 50% |

Вывод: **Δ precision — артефакт измерения, а не деградация краулера.** Независимый AI-judge (6.7) сходится с W28/W29 (8.0 / 7.8) в пределах шума на n=12, а не с 1.5.

Вторая проблема той же метрики: `feedback.last_7d` смешивает разметку из разных режимов. 774 строки идут пачками до 18/минуту, 438 из 774 (57%) — из одного источника `TG: PR Media Group`. Precision по всей системе фактически меряется одним шумным TG-каналом.
